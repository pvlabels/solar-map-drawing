# Solar Map Drawing

Produce a faithful, simplified vector map that can later be placed into a placard. Treat the source as evidence about the site and finished examples as evidence about drawing style. Do not substitute an example site's geometry for the current job.

Use the bundled `scripts/map_workbench.py` with Python, PyMuPDF, and Pillow. It works independently of the old vector app, Claude, Chrome, and SKU registry. Resolve script paths relative to this skill. Deliver one **WO-named SVG per sales order** unless the user asks for more. Place all maps for the same order on that SVG's single artboard, with clear space and a source-confirmed item label above each map. Keep reusable scenes, extraction data and internal QA in the project's `tmp/solar-map-drawing/JOB/`, outside both the delivery folder and skill package. Read [references/scene-format.md](references/scene-format.md) when constructing a scene.

## Work efficiently

For an existing job, reuse its cached scene and extraction manifest when the source hash still matches. A callout-only revision changes text positions and leader routes; keep geometry, map fit, rotation, equipment targets, north direction and physical stroke weights unchanged. Do not re-inspect the packet, retrace the map, regenerate full comparisons or reread style examples for this kind of edit. Check the changed area in one internal preview and verify that geometry and stroke attributes stayed identical.

For a new map, inspect and extract once, then reuse that extraction throughout revisions. Generate the full diagnostic comparison for the initial geometry review or when geometry/source uncertainty warrants it. Routine iterations need only a preview. Auxiliary exports are optional and are not customer deliverables by default. New raster inputs still require careful tracing; reduce repeated work rather than omitting source verification.

## Find and inspect the actual drawing

For a new job, run `inspect SOURCE --output WORK/inspection` and view the contact sheets, where WORK is the internal job folder above. Every page is indexed. Select the page and map region visually; an outlined invoice can have thousands of vectors and no readable text. More vectors does not mean a better map.

Run `extract SOURCE --page N --clip X0 Y0 X1 Y1 --output WORK/source`. Page numbers are **one-based** and crop coordinates are **displayed page points**, matching `pages.json`. The crop should contain the complete relevant map, including equipment and north arrow. Headers and template borders can be excluded. Inspect `source.png` before tracing. If no map exists, say so; never invent one from a shipping address or another job.

Inventory the buildings and their relative placement, footprint concavities, roof junctions, individual module groups, equipment locations, streets and north direction. Record unresolved details in the scene's `uncertainties`. Read critical callout wording from source text when available and verify it against the image.

Identify the work order and count its distinct maps. For multiple maps, match each map's A/B/etc. mark to its order line and record `job.work_order`, `job.map_count`, `job.item_letter` and `job.item_evidence` in its scene. Use confirmed letters, with labels such as `WO-288697-A` and `WO-288697-B`. If a letter is unclear, complete the geometry and confirm the mapping before export. Render the order scene that lists all map scenes. The combined artboard places each map at its reviewed size, with its own geometry and callouts in an editable group.

## Choose how to draw

**Vector map:** use `manifest.json` and `path-atlas.png` to select source path IDs by role. Preserve coordinates, curves, path closures, and individual panel corners in the source trace; apply the required site rotation during final rendering. Source paths are candidates, not automatically buildings. Inspect combined paths before using them: they may contain leaders, glyphs, or unrelated sheet furniture. If a path mixes roles, split it explicitly into scene paths, copying its commands and noting which source path was split. Identify the complete exterior perimeter separately from interior roof edges so every exterior segment receives the correct weight.

**Raster or hand sketch:** trace in the same displayed page coordinate system. Use shared vertices for connected roof junctions. Preserve the observed outline, offsets between buildings, panel grouping, and equipment attachment points. Make each panel an individual polygon when arrangement is irregular. Regularize rough strokes only enough to clarify the intended geometry, and record that interpretation. Do not claim survey accuracy. A photo's ruled paper or perspective distortion is not roof geometry.

**Hybrid input:** combine exact source paths and explicit traced elements. Check the rendered source for clipping or visibility that the path inventory may not capture.

Keep every added element tied to a source feature through a source ID or `evidence` note. Do not assume every closed loop is a building, every rectangle is a panel, or every interior line is a ridge. Avoid global line merging, minimum-area deletion, and bounding-box replacement of rotated panels. Straightening is a single rigid rotation of the site, not independent snapping or deformation of individual edges.

## Map drawing decisions

- Prioritize building topology and placement, then roof structure, then panels, equipment and orientation. Keep vector geometry at source proportions until the map is correct.
- Retain distinct buildings, concave corners, stepped panel arrays, missing grid cells, and actual roof intersections. Do not regularize an irregular array into a full rectangular grid.
- Equipment stays where the source puts it. An explicitly indoor service panel must not be moved outside by a styling rule. Small marks can later be standardized without moving their attachment points.
- **Automatically rotate to the nearest flat orientation:** main walls may be horizontal/vertical or at 45 degrees. The renderer selects the nearest multiple of 45 degrees from the main outline's dominant wall direction. With multiple structures, square up the main structure and rotate the entire site together; never straighten structures independently. Assign a shared `structure_id` to all fragments of each building. Specify `alignment.primary_structure` when the main structure is known; otherwise the largest outline bounding area is used.
- **Use the same north symbol every time:** `assets/north-arrow.json` contains the canonical needle from the finished references: outlined left half, filled right half, upright N below. Keep its default 34 pt needle height unless the user requests another size. Use `north_arrow` metadata instead of selecting the customer's compass paths. First compensate source north by the applied site rotation. Then snap the displayed needle to the nearest multiple of 45 degrees **only when within plus or minus 10 degrees**, per the user's appearance preference; retain the compensated angle outside that tolerance. Keep raw and displayed angles in the internal report. An explicit user correction for a particular job can set `display_rotation_deg` with `display_rotation_evidence`. Keep the N and callout text upright. Never invent a north direction when the source does not supply one.
- **Exact physical stroke weights:** exterior building perimeter **2 pt**, interior roof lines **1 pt**, solar panels **1.25 pt**, equipment **1.5 pt**. These weights do not change with the map's fit scale. Final SVG dimensions are in physical points with one viewBox unit per point. Leaders use the references' thin 0.75 pt style. Recheck weights if scaling the SVG in another application.
- **Include callouts by default:** uppercase Arial/Helvetica text, clear line breaks, thin elbow leaders, and **Illustrator Arrow 2 at 100% scale on a 0.75 pt stroke**, with its tip at the leader endpoint. `assets/leader-arrow-2.json` contains the actual Arrow 2 proportions. End the shaft inside the head so a blunt stroke cannot protrude beyond the sharp tip. The SVG represents this as matching editable vector shapes, not an Illustrator-native Stroke-panel setting. Preserve the equipment wording, N/E designators, and correct target. Keep text outside building geometry where practical; make routes horizontal/vertical with short terminal approaches. Use small white clearances at necessary geometry crossings, as the examples do. Include solar-array and building/context labels when shown or established by the source. Defer callouts only when the user explicitly requests a geometry-only proof.
- **Keep callouts compact:** place labels near their targets, use short leaders and few elbows, and tighten spacing while retaining readable separation. Stagger nearby equipment labels around the available space instead of forcing them into a distant column. Shorten routes by moving labels, never by moving equipment, changing the map geometry/fit, or reducing the required line weights. Do not sacrifice clear target identification to save space.
- **Leave a visible gap at every arrowhead.** Check the whole head against the drawn target outline, including the stroke and nearby shapes. The renderer starts with a 3 pt setback from the target coordinate and increases it to clear nearby geometry by 2 pt. Approach from another direction when shortening the leader would leave its tip pointing at an intervening edge. Inspect crowded targets at high zoom and at reading size.
- Fit the rotated map into a point-based map box, then lay out callouts in output points. Callout targets remain source coordinates and follow the map transform automatically. Check label/leader collisions visually; the renderer warns about overlapping labels and out-of-bounds placement but does not solve routing.
- The current user-confirmed rotation, north symbol, callout, and stroke rules supersede conflicting historical rules in the old app or the initial assessment. Template headers, footer stamps and product sizing remain deferred unless requested.

## Render and verify

Run `render WORK/scene.json --output DELIVERY` for one map or pass `WORK/order.json` for the shared artboard. The default writes only the WO-named SVG. The report's `output_filename` is authoritative. Add `--preview WORK/preview.png` for a quick internal visual check. Add `--diagnostics WORK/qa` when a full source comparison, unrotated trace, overlay and saved report are needed. Review the arrow gaps, item labels and space between maps in the combined preview. The renderer reports `needs_visual_review` until the artwork has been checked visually.

For new or changed geometry, open the internal comparison and overlay. Follow the entire building perimeter and check every concave corner. Check each roof junction, count individual modules, verify equipment count and side of the wall, and compare north direction. Inspect at high zoom and at the likely reading size. The overlay checks the original unrotated geometry; the clean map must also be checked for a flat main structure, compensated canonical north symbol, exact stroke weights, and readable correctly targeted callouts. Callout-only edits require a focused preview check and geometry/stroke equality verification instead of repeating that full review.

Correct the scene and rerender until the known errors are resolved. If the source cannot resolve a critical detail, deliver a marked draft with that uncertainty instead of silently guessing. Keep the extraction manifest unchanged so corrections stay traceable. Record actual visual observations and remaining limitations briefly in the internal scene or QA note, outside the delivery folder; do not label a map approved solely because a model said MATCH.

Return the editable SVG link with a concise description of what changed and any unresolved detail. Provide previews, comparisons, reports or other extra files only when requested; an internal visual check is still required. Fit into a specific placard only when that is part of the request. Do not rename a PDF to `.ai` and present it as a native Illustrator document.
